Set up a GitHub Pages repository

How to turn a folder of exported ELI5 Learner documents into a website with a GitHub Actions workflow. This works for any repository and any owner.

1. What you get

Every document pushed to <docsPath>/<slug>/index.html becomes reachable at https://<owner>.github.io/<repo>/<slug>/. Documents are plain, self-contained static HTML, so no site generator is needed.

2. Prerequisites

  • A repository you can push to.
  • git installed on your Mac.
  • Working git credentials for that repository (a credential helper or an SSH key). If your credential helper asks the macOS Keychain for access, grant it once from a terminal so later pushes never need a prompt.

Plans: on GitHub Free, Pages can be published only from a public repository. Publishing Pages from a private repository requires a paid plan, and even then the site itself is public. Only GitHub Enterprise Cloud can restrict a Pages site to organization members (private Pages).

3. Create or choose the repository and folder

Use a dedicated repository, or a dedicated docs/ folder in an existing one. Add an empty docs/.nojekyll file so files and folders whose names start with _ are served as they are. Optionally add docs/index.html as a landing page that links to your documents.

4. Enable Pages with Actions as the source

In the repository on GitHub, open Settings, then Pages, then Build and deployment, and set Source: GitHub Actions.

5. Add the workflow

Create .github/workflows/pages.yml:

name: Deploy docs to GitHub Pages
on:
  push:
    branches: [main]
    paths: ["docs/**", ".github/workflows/pages.yml"]
  workflow_dispatch:
permissions:
  contents: read
  pages: write
  id-token: write
concurrency:
  group: pages
  cancel-in-progress: false
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v7
      - uses: actions/configure-pages@v6
      - uses: actions/upload-pages-artifact@v5
        with:
          path: docs
      - id: deployment
        uses: actions/deploy-pages@v5
  • on: the workflow runs only when something under docs/ (or the workflow itself) changes on main, or when you start it by hand.
  • permissions: least privilege; id-token: write is required by the deploy action.
  • concurrency: two pushes in a row deploy one after the other instead of racing.
  • path: must match the folder the documents are pushed to (the app's docs path).

Use the current major versions of the four actions. The versions above match the workflow this app's own repository uses.

6. Branch protection and required reviews

If main requires pull requests, direct pushes are rejected. Either publish to an unprotected branch and change the workflow's branches trigger to that branch, or keep publishing manual through pull requests.

7. Keep private material out

Only index.html files are ever pushed for a document. If the repository also holds other generated files, ignore the whole folder and allowlist only what should be public in .gitignore: 

docs/*
!docs/index.html
!docs/.nojekyll
!docs/<published-slug>/

8. Custom domain (optional)

Add the domain under Settings, then Pages, then Custom domain, and update the Pages URL pattern in the app's settings to match.

9. Configure the app

On GitHub App setting
Repository (owner/name) publish.github.repo
Branch publish.github.branch
Folder publish.github.docsPath
Site URL publish.github.pagesUrlPattern

Pushing from the app is available in the enterprise edition only. In this edition these settings are dormant: use Export copy, then copy the exported folder into your repository's docs folder and push it yourself.

10. Verify

  1. Push a test document to docs/<slug>/index.html.
  2. Open the repository's Actions tab and wait for the deploy job to finish.
  3. Note the page_url the deploy job reports.
  4. Open <page_url><slug>/ in your browser.

11. Troubleshooting

  • 404 right after a push: the deploy is still running, or the workflow's path does not match the folder you pushed to.
  • Styles or scripts missing: none are expected, since documents are self-contained. Check that docs/.nojekyll exists.
  • The workflow did not run: the change was outside the paths filter, or the Pages source is not set to GitHub Actions.
  • Push rejected: branch protection, a non-fast-forward (pull first, then push again), or the code host's secret scanning blocked something that looks like a credential.
