# Testing and quality

This file specifies how ELI5 Learner is verified: the test pyramid and its tools (Vitest for unit and integration, Playwright `_electron` for end-to-end), the synthetic fixture corpus committed to this public repo, the LLM fakes and recorded HTTP cassettes that keep every CI run offline, the document validity checks every generated `index.html` must pass, the rubric-based LLM-judge evals that measure generation quality for the In depth and ELI5 tabs, public-repo hygiene checks, the GitHub Actions CI on a macOS runner, and the edition matrix (the public build must pass with no overlay; enterprise contract tests run only when a private overlay is present). It implements the verification side of every PRD section, most directly "Build editions and swap seams" (public build runs with nothing but an API key; clean swap seams), "Inputs and extraction", "Fetching strategy", "Processing pipeline", "Output document" (self-contained file, stable section IDs), "Interactive reading", and "Library, storage, and merge suggestions".

Related: [01-architecture.md](01-architecture.md) · [02-llm-provider.md](02-llm-provider.md) · [03-source-resolvers.md](03-source-resolvers.md) · [04-extraction.md](04-extraction.md) · [05-url-fetching.md](05-url-fetching.md) · [06-generation-pipeline.md](06-generation-pipeline.md) · [07-output-document.md](07-output-document.md) · [08-interactive-reading.md](08-interactive-reading.md) · [09-library-storage.md](09-library-storage.md) · [10-publishing.md](10-publishing.md) · [11-app-shell-ui.md](11-app-shell-ui.md) · [12-configuration-security.md](12-configuration-security.md)

## 1. Principles

1. **Offline by default.** No test in the default suites touches the network, a real LLM, the real macOS Keychain, or the user's library. Network access in a unit or e2e test is a test failure, not a flake.
2. **Deterministic.** Clock, random source, timezone, and locale are injected or pinned. The same commit produces the same results on every run.
3. **Synthetic, public fixtures only.** Every committed fixture is authored for this repo, is generated by a committed script where practical, and contains no real organization's content. Realistic private material belongs to HOOK-TEST-02.
4. **Public build is the gate.** `ELI5_EDITION=public` with no overlay must pass every required suite. Enterprise-only suites are additive and never required for a public merge.
5. **Stubs are tested as stubs.** Each public stub (`bedrock.stub.ts`, `mcp.stub.ts`, `drive.stub.ts`, `git.stub.ts`) has a test that it throws `NotAvailableInEdition` with the right `hookId` and makes no network call ([01 §6.4](01-architecture.md)).
6. **Contracts over implementations.** Each swap seam (`LLMProvider`, `SourceResolver`, `Extractor`, `Publisher`, `AuthBroker`, `EditionOverlay`) has one reusable contract suite. Public implementations run it in CI; private implementations run the same suite under HOOK-TEST-01.
7. **Quality is measured, not asserted.** Generation quality is scored by rubric evals with stored baselines. Evals are never a per-PR gate, because they need a real key and are non-deterministic.

## 3. Test pyramid

| Layer | Tool | Scope | Runs | Budget |
| --- | --- | --- | --- | --- |
| Static | `tsc` strict, ESLint (incl. import boundaries), Prettier | Whole repo | Every push | < 2 min |
| Unit | Vitest (`node` env for main; `jsdom` env for renderer and doc-runtime) | One module, all collaborators faked | Every push | < 90 s total |
| Integration | Vitest `node` | Pipeline, library, document builder together with `FakeProvider`, fixture server, temp library | Every push | < 3 min |
| Contract | Vitest | Each seam implementation against its contract suite | Every push (public); private CI (enterprise) | < 1 min |
| Document validity | Vitest + hidden `BrowserWindow` probe in e2e | Every golden and every e2e-generated `index.html` | Every push | inside unit/e2e budgets |
| End-to-end | Playwright `_electron` against the built public app | User flows through the real UI | Every push to PR and `main` | < 10 min |
| Cross-browser smoke | Playwright Chromium and WebKit | Golden documents opened as files | Every push | < 2 min |
| Evals | Vitest runner + real providers + LLM judge | Generation quality | Nightly and manual | cost-capped (§9.6) |

### 3.1 Coverage targets

Measured with `@vitest/coverage-v8` over `src/main/**` and `src/doc-runtime/**`, unit + integration combined.

| Area | Line coverage floor | Notes |
| --- | --- | --- |
| `extract/`, `document/`, `library/`, `pipeline/`, `config/`, `editions/` | 85% | Deterministic logic; high bar |
| `sources/`, `fetch/`, `publish/`, `llm/`, `photos/` | 75% | I/O-heavy; rest covered by contract and e2e |
| `doc-runtime/` | 80% | jsdom tests of tabs, glossary collapse, selection bridge |

### 3.2 Determinism and isolation

- `TZ=UTC`, `LANG=en_US.UTF-8` are set in `config/vitest.config.ts` and `config/playwright.e2e.config.ts`.
- `Clock` and `IdSource` are constructor-injected in `pipeline/`, `document/`, and `library/`. `SeededIdSource(seed)` yields a reproducible 8-hex sequence so golden files contain stable SectionIds (`sec-indepth-3f9a1c2e` format, [07](07-output-document.md)).
- `net-guard.ts` is a Vitest `setupFiles` entry that replaces `net.Socket.prototype.connect`, `globalThis.fetch`, and `undici`'s global dispatcher with functions that throw `NetworkAccessInTest` unless the target is `127.0.0.1` on a port owned by `fixture-server.ts`. Suites that intentionally reach the network (evals, cassette recording) opt out explicitly.
- Every test that writes files uses `tmpLibrary()`, which creates a fresh directory under the OS temp dir, sets `ELI5_LIBRARY_DIR=<tmp>/docs` and `ELI5_USER_DATA_DIR=<tmp>/userData` for the code under test ([09 §3.1](09-library-storage.md), [12](12-configuration-security.md)), and deletes the directory in `afterEach`. No test writes under `<repo>/.library/` or `<repo>/docs/`.
- The Keychain port ([12](12-configuration-security.md)) is replaced with `MemoryKeyStore` (selected by `ELI5_KEYSTORE=memory`, honored only when `!app.isPackaged`; `fake-keychain.ts` is the unit-test wrapper around it) in all suites except one opt-in local test (`test/unit/main/config/keychain.real.test.ts`, skipped unless `ELI5_TEST_REAL_KEYCHAIN=1`). E2E seeds it from `ELI5_TEST_API_KEY_*` variables.

### 5.2 Manifest

```ts
// test/fixtures/manifest.json is validated against this type in a unit test
export interface FixtureManifest {
  version: 1;
  fixtures: FixtureEntry[];
}
export interface FixtureEntry {
  path: string;                    // relative to test/fixtures/
  format: 'pptx' | 'docx' | 'pdf' | 'pdf-scanned' | 'xlsx' | 'image' | 'md' | 'txt' | 'html' | 'unsupported' | 'hostile';
  generator?: string;              // build script path; absent = hand-written
  sha256: string;                  // of the committed binary
  expect: {
    kind: 'extract' | 'skip';
    golden?: string;               // expected.txt path for kind 'extract'
    skipCode?: string;             // SkipCode for kind 'skip' (03, 04)
    imageCount?: number;           // images sent to vision
  };
  provenance: 'synthetic';         // only allowed value in the public repo
}
```

### 5.3 Rules and edge cases

1. `manifest.test.ts` fails if any file under `test/fixtures/sources/` or `sites/` is missing from the manifest, if a `sha256` does not match, or if `provenance` is anything but `synthetic`.
2. `npm run fixtures:build` regenerates binaries; CI runs it in a scratch dir and compares extracted text (not bytes, since zip timestamps differ) against goldens to prove the generators still describe the committed files.
3. Updating a golden requires `npm run test:update-goldens`, which rewrites `*.expected.txt` and `documents/*.html` and prints a diff summary. Reviewers must see the diff in the PR.
4. Fixture size cap: 2 MB per file, 20 MB total. Larger cases are generated at test time into the temp dir (e.g. a 500-page PDF for the page cap).
5. Fixtures must pass the hygiene scan (§11) like any other tracked file.

## 6. LLM fakes and recorded responses

### 6.1 FakeProvider

`FakeProvider implements LLMProvider` lives in `src/main/llm/testing/fake.ts` ([02 §16](02-llm-provider.md)). It is not a new provider id (`llm.provider` stays `'claude'|'openai'|'bedrock'`, [12](12-configuration-security.md)). Only when `ELI5_LLM_FAKE=1` and the build defines `__ELI5_TEST__` (true for `dev` and test builds, false for `package`), bootstrap calls `registry.registerLLMProvider(<current llm.provider>, () => fake)` after the public registrations, so the active provider id is replaced by the fake ([01](01-architecture.md), [02](02-llm-provider.md)). A packaged build contains no fake provider; a unit test greps `out/main` of a `package`-mode build for the string `FakeProvider` and fails if found.

```ts
export interface FakeScript {
  /** Response JSON files keyed by 02 PromptId (e.g. "in-depth", "eli5", "glossary", "summary", "section-expand"). */
  responses: Partial<Record<PromptId, string | string[]>>;  // array = successive calls
  errors?: Partial<Record<PromptId, LLMErrorKind | LLMErrorKind[]>>;  // inject per task, per call
  latencyMs?: number;                              // default 0; e2e uses 50 to make status visible
  truncateTask?: PromptId;                          // simulate max_tokens truncation for one task
}
```

Behavior:

1. Resolve the task id from `GenerationRequest.taskId` ([02](02-llm-provider.md)). Unknown task → throw `LLMError('bad_request')` with the id in the message, so missing fixtures fail loudly.
2. If `errors[taskId]` has an entry for this call index, throw that `LLMErrorKind`.
3. Otherwise return the fixture JSON as `GenerationResult`, with token usage computed as `ceil(chars/4)` so budgeting code sees plausible numbers.
4. Record every request (system, messages, image count, byte sizes) in `fake.calls` for assertions (e.g. "scanned PDF sent 3 images", "clarifying input appears in the user message").

The script is loaded from `ELI5_LLM_FAKE_SCRIPT` (path) or defaults to `test/fixtures/llm/default.json`, which produces a complete, valid document for any input.

### 6.2 Recorded responses for draft fixtures

The JSON under `test/fixtures/llm/` is real model output captured once and then frozen, so builder and validity tests exercise realistic drafts (long sections, charts, glossary entries). `npm run llm:record -- --task in-depth --source <fixture>` runs the real provider (key from Keychain or `ELI5_RECORD_KEY`), validates against the `DocumentDraft` schema, and writes the file. Recording is manual and local; CI never records.

### 6.3 Provider HTTP cassettes

Provider contract tests for `claude.ts` and `openai.ts` run against cassettes, not a fake provider, to cover SDK wiring.

- Both SDK clients accept an injected `fetch`. Tests inject `cassetteFetch(cassettePath)`, which matches requests by method, URL path, and a normalized body hash (model name and `max_tokens` kept, whitespace normalized), and replays status, headers, and body. Streaming bodies are replayed chunk by chunk.
- Unmatched request → test failure with a diff of the nearest recorded request.
- Recording mode (`ELI5_CASSETTE_RECORD=1`, local only) writes new cassettes. The writer strips `authorization`, `x-api-key`, `cookie`, `set-cookie`, organization or project id headers, and any request-id headers, and fails if the body contains the key string.
- Required cassettes per provider: text generation, image input, structured output success, schema rejection then repair, 401, 400, 429 with `retry-after`, 5xx overloaded, context overflow, streamed response.

### 6.4 Fixture web server

`fixture-server.ts` serves `test/fixtures/sites/` on `127.0.0.1:<random>` with scripted behaviors: `/spa/` returns an empty shell whose content is injected by inline JS after 300 ms; `/login-wall/` returns 200 with a password form; `/paywall/` returns a truncated article with a subscribe overlay; `/redirect-loop/` redirects forever; `/slow/` stalls past the fetch timeout; `/binary/deck.pptx` serves a fixture with a PPTX content type. Fetch unit tests and e2e URL tests use it; the hidden-window fallback in e2e loads from it, proving the fallback works without the internet.

## 7. Document validity checks

`validateDocument(html: string, meta?: DocumentMeta): ValidityReport` in `test/helpers/doc-validity.ts`. The same checks (static part) are also compiled into `src/main/document/validate.ts` and run by the builder before every save and every regenerate-in-place write, so an invalid document is never written ([07](07-output-document.md)). An error-level failure at save time is logged and the job fails with `SAVE_FAILED` rather than writing a broken file. Warning-level results (currently only `size`) never block a save.

```ts
export interface ValidityReport { ok: boolean; errors: ValidityError[]; warnings: ValidityError[]; stats: { bytes: number; sections: number; tabs: number } }
export interface ValidityError { rule: ValidityRule; detail: string; sectionId?: string }
export type ValidityRule =
  | 'parse' | 'single-file' | 'no-external-ref' | 'csp' | 'section-id-format' | 'section-id-unique'
  | 'section-id-mirror' | 'tabs-match-meta' | 'default-tab' | 'glossary-scope' | 'references'
  | 'no-inline-handlers' | 'photo-credit' | 'size';
```

### 7.1 Static rules

| Rule | Check |
| --- | --- |
| `parse` | Parses with `parse5` with zero errors in the `<html>`, `<head>`, `<body>` structure; exactly one `<html>`. |
| `single-file` | No `<link rel=stylesheet href>`, no `<script src>`, no `<iframe>`, `<object>`, `<embed>`. All CSS and JS inline. Images only as `data:` URIs or inline SVG. |
| `no-external-ref` | No attribute (`src`, `href` on non-anchor elements, `srcset`, `poster`, `action`, `formaction`, `xlink:href`) and no CSS `url(...)` / `@import` resolves to `http:`, `https:`, `//`, `file:` or a relative path. Anchor `href` may be external (references list) but must carry `rel="noopener noreferrer"` and `target="_blank"`. |
| `csp` | `<meta http-equiv="Content-Security-Policy">` present, placed in `<head>` before any `<style>` or `<script>`, and at least as strict as the policy in [07](07-output-document.md) (`default-src 'none'`, no `connect-src` other than `'none'`); its `script-src` hash matches the embedded runtime script. |
| `section-id-format` | Every `<section>` in a tab panel has `id` matching `SECTION_ID_RE` imported from `src/main/document/model.ts` (07 §3: `^sec-[a-z][a-z0-9]{1,15}-[0-9a-f]{8}$`; not restated in test code), and the tab key segment equals the enclosing tab's key. |
| `section-id-unique` | No duplicate `id` anywhere in the document (not just among sections). |
| `section-id-mirror` | `data-section-id === id` on every section. |
| `tabs-match-meta` | Tab keys and order equal `meta.tabs` when `meta` is given; `indepth` and `eli5` always present; every tab button in `nav.tabbar` controls exactly one panel and every panel has one button. |
| `default-tab` | `indepth` is the initially active tab. |
| `glossary-scope` | Glossary callouts appear only inside the `indepth` panel. |
| `references` | `indepth` ends with a references section listing every `meta.sourcesUsed` and `meta.sourcesSkipped` entry (with reason). |
| `no-inline-handlers` | No `on*=` attributes; runtime wires events from its own script. |
| `photo-credit` | Every `figure.stock-photo` contains a `.fig-credit` with a `.fig-license` ([07 §7.4](07-output-document.md)). |
| `size` | Warning only, never an error: `bytes` > 25 MB adds a `size` entry to `warnings` ([07 §5.4](07-output-document.md) is the single source for this limit). |

### 7.2 Runtime rule: zero network requests

Static checks cannot see requests made by script. In e2e, `probeDocument(path)` opens the file in a hidden `BrowserWindow` with a dedicated partition whose `session.webRequest.onBeforeRequest` records and cancels every request whose scheme is not `file:` (for the document itself) or `data:`. After load, it switches through every tab, toggles every glossary note, and resizes below the glossary breakpoint. Pass condition: zero recorded requests and zero console errors. This runs on every golden document and on every document produced by an e2e flow (`probeDocument` in `test/e2e/harness.ts`, called by the harness's `generate` helper). The cross-browser suite (§7.3) applies the same rule in Playwright Chromium and WebKit: request interception records and aborts every request other than the document and `data:` URIs, and CSP violation events count as failures.

### 7.3 Cross-browser smoke

The PRD requires the file to open in Chrome, Safari, and Edge. Playwright opens each golden via `file://` in Chromium (covers Chrome and Edge engines) and WebKit (Safari engine): the default tab renders, tab switching works, glossary collapses at narrow width, and there are no page errors. The select-and-act bridge is absent outside the app and must fail silently ([08](08-interactive-reading.md)). Selection zones (`selection-zones.spec.ts`, [08](08-interactive-reading.md) §5.6): a real mouse drag across body paragraphs next to a glossary note leaves the note out of the selection, its computed `user-select` is `none`, and a copy carries no note text; a drag that starts inside a note stays inside it, wide and narrow.

## 9. Generation quality evals

### 9.1 Purpose and cadence

Evals answer "did a prompt, skill, or model change make documents better or worse?". They run nightly on `main`, on manual dispatch, and locally via `npm run eval -- --provider claude --model <id>`. They need real API keys (CI secrets). Results are reported, compared to a baseline, and never block a PR merge; a nightly regression opens a tracking issue.

### 9.2 Eval set

`test/evals/cases/*.json`, 12 to 20 cases, each referencing synthetic fixtures (§5) and an optional clarifying input:

```ts
export interface EvalCase {
  id: string;                         // "finance-deck-glossary"
  sources: string[];                  // fixture paths
  clarifying?: string;
  glossary: boolean;
  domain: 'security' | 'finance' | 'marketing' | 'data' | 'general';
  mustCover: string[];                // key facts the doc must convey (checked by judge)
  jargon: string[];                   // terms the glossary / ELI5 must handle, e.g. "ROAS"
  sectionActions?: {
    action: 'expand' | 'reexplain' | 'analogy' | 'deeper' | 'section-eli5'; // section-eli5 = 08 MenuAction 'eli5-tab'
    sectionHint: string;
    note?: string;                    // user note; S3 is scored only when given
  }[];
  covers?: string[];                  // bookkeeping only: which coverage requirements the case satisfies
}
```

Coverage: every PRD source type, at least 3 cases per domain named in the PRD, at least 2 multi-source cases, one case with a skipped source, one with images only.

### 9.3 Pipeline per case

1. Run the real generation pipeline headless (integration harness, real provider, `SeededIdSource`).
2. **Deterministic gates first:** `validateDocument` must pass; required tabs present; glossary present iff enabled; each `jargon` term appears in a glossary callout (In depth) when enabled. A gate failure scores the case 0 without calling the judge.
3. **Judge:** for each tab, send the extracted source text, the tab's visible text (HTML stripped, figure captions and chart data kept as text), and the rubric to the judge model. The judge returns JSON `{ scores: Record<criterionId, 1|2|3|4|5>, rationale: Record<criterionId, string>, missingFacts: string[] }`.
4. Run section actions if listed; judge the replaced section (or the new Section ELI5 tab) with the section-action rubric: S1 and S2 always, S3 only when the action carries a `note`.
5. Repeat judging 3 times; take the median per criterion.

### 9.4 Rubrics

In depth tab:

| ID | Criterion | 5 means |
| --- | --- | --- |
| `D1` | Accuracy | No claim contradicts or goes beyond the sources; numbers match |
| `D2` | Coverage | Every `mustCover` fact is conveyed |
| `D3` | Calibration | Explains what a non-expert reader would not know; does not re-explain the obvious |
| `D4` | Explanatory structure | Leads with the point, builds logically, headings are informative |
| `D5` | Visual explanation | Charts, diagrams, or annotated figures carry real information and match the data (WSJ-grade bar, PRD "Output document") |
| `D6` | Glossary quality | Terms are the ones the original audience assumed; explanations are short and correct (N/A when off) |
| `D7` | References | Every used and skipped source listed correctly |

ELI5 tab:

| ID | Criterion | 5 means |
| --- | --- | --- |
| `E1` | Plain language | No unexplained jargon; `jargon` terms replaced by plain words |
| `E2` | Rebuilt structure | Organized for comprehension, not a mirror of the source outline (PRD) |
| `E3` | Faithfulness | Simplifications do not become false |
| `E4` | Core idea | A reader can state the main point after one read |
| `E5` | Analogies | Analogies are apt and not misleading |

Section actions: `S1` action honored (expanded / clearer / analogy / deeper / focused ELI5), `S2` consistent with surrounding sections, `S3` user note honored when given.

### 9.5 Judge calibration

- Judge model and provider are configured separately from the generator (`ELI5_EVAL_JUDGE=provider:model`); by default the judge uses the other public provider to reduce self-preference when its key (`ELI5_EVAL_API_KEY_<PROVIDER>`) is set, and otherwise the generator's provider. Keys come only from `ELI5_EVAL_API_KEY_CLAUDE` / `ELI5_EVAL_API_KEY_OPENAI` (CI maps the `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` secrets onto them). A model without an entry in the devtools rate table needs `ELI5_EVAL_RATES=<model>=<in>:<out>`, or the run is refused before any call.
- Each rubric ships 2 anchor examples (a score-2 and a score-5 excerpt from synthetic material) included in the judge prompt.
- `test/evals/calibration/` holds 10 hand-scored documents. `npm run eval:calibrate` reports judge vs human agreement; a judge change is accepted only if mean absolute error ≤ 0.75 per criterion.

### 9.6 Scoring, baselines, cost

- Case score = mean of median criterion scores; suite score per tab = mean of case scores. Gate and generation failures count as 0 in suite scores but are left out of per-criterion means; `judge_error` and `skipped_budget` cases are left out of both. Stored in `test/evals/results/<date>-<provider>-<model>.json` (CI artifact; only baselines are committed).
- Regression rule: a suite score drop > 0.3, or any criterion mean drop > 0.5, vs `test/evals/baselines/<provider>.json` is a regression. It is evaluated over the cases present in both the run and the baseline, and only for complete runs. `scripts/eval/run.mjs` exits 2 on a regression, which the CI job turns into an issue. Baselines are updated only by a PR that includes the results file.
- Cost cap: `ELI5_EVAL_MAX_USD` (default 10). The runner estimates cost from token usage and stops scheduling new cases once the cap is reached, reporting partial results as `incomplete`.
- Eval runs never run on pull requests from forks and never print source text or model output to logs; the report contains scores, rationales, and missing facts only.

### 10.2 Contract suites

Each suite is a function taking a factory, so public and private code run identical assertions:

```ts
export function describeLLMProviderContract(name: string, make: (scenario: ContractScenario) => Promise<LLMProvider>, opts: { transport: 'cassette' | 'fake' | 'live'; errorKinds?: LLMErrorKind[] }): void;
export function describeSourceResolverContract(name: string, make: () => Promise<SourceResolver>, cases: ResolverContractCase[], opts?: ResolverContractOptions): void;
export function describeExtractorContract(name: string, make: () => Extractor, cases: { fixture: string; golden?: string }[]): void;
// `fx` is a temp library with one document and an export folder; `delivered` lets the suite read back
// what reached the destination ("exactly the file set", "nothing uploaded").
export function describePublisherContract(name: string, make: (fx: PublisherFixture) => Promise<Publisher>, target: PublishTarget, opts?: { scansBeforeUpload?: boolean; delivered?: () => Promise<string[]> }): void;
export function describeAuthContract<B extends AuthBroker>(name: string, make: () => Promise<B>, opts?: { interactions?: (b: B) => number }): void;
export function describeOverlayContract(overlay: EditionOverlay): void;
```

Minimum assertions:

- **LLMProvider:** text and image requests return `GenerationResult` with usage; `generate` rejects images; each error class maps to the documented `LLMErrorKind`; structured output validates or the repair path runs once; `testConnection` never throws.
- **SourceResolver:** `canResolve` is pure; every input yields a `ResolvedSource` or `SkippedSource {ref, reason}`; abort signal honored within 1 s; no credential material in `ResolvedSource`, notes, or logs (scan for token-like strings).
- **Extractor:** output validates as `ExtractedContent`; `toPromptText` deterministic.
- **Publisher:** publish only the documented file set ([10 §3.3](10-publishing.md)); returns `PublishResult` with a link or a typed error; idempotent republish; secret scan runs before upload for publishers whose target is remote (kind `git`; `drive` per HOOK-PUB-05). The local publisher is not required to scan.
- **AuthBroker** ([03 §12](03-source-resolvers.md)): `status()` never triggers interaction; the app never receives a token (no token-shaped values cross the interface).
- **EditionOverlay:** `apiVersion === OVERLAY_API_VERSION`; `register` completes within 5 s; after registration no registered stub remains for a capability the overlay claims; `freeze()` succeeds.

## 14. Error handling and edge cases

| Case | Behavior |
| --- | --- |
| Test opens an unexpected socket | `net-guard` throws `NetworkAccessInTest` naming host and port; test fails |
